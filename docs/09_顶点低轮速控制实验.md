# 顶点平衡低轮速控制实验

更新：2026-10-05。范围先限定为 `point_balance`（从顶点附近起步）；既有 `fast`、棱平衡预设和起立到顶点的模式保持原控制路径。

## 目标与当前结论

棱平衡已有 `edge_low_speed` 和 `edge_near_zero`。本轮希望顶点平衡也能在捕获后卸掉三只飞轮的转速。新增两个独立实验预设：

| 预设 | 顶点轮速比例反馈 `KwPoint` | ODE5 @ 0.125 ms、3° 初始滚转、60 s 的末 10 s 三轮合成轮速峰值 |
|---|---:|---:|
| `point_low_speed` | `3e-5 N·m·s/rad` | `5.406 rad/s` |
| `point_near_zero` | `7e-5 N·m·s/rad` | `2.315 rad/s` |

`point_near_zero` 的同配置 300 s 试验末段仍为约 `2.315 rad/s`，顶点倾角约 `0.001°`，没有后期轮速爬升。**这不是严格收敛到零，也不是数值收敛证明。**把局部求解步长从 0.25 改到 0.125、0.0625 ms，三轮末段峰值分别约 `1.428 / 2.315 / 6.121 rad/s`。当前只把 ODE5 @ 0.125 ms 下的结果称作可复现的实验候选。

两套新预设目前**只支持 `point_balance`**。`flat_to_point`、`edge_to_point` 等起立链到达顶点时，飞轮可能留有数百 rad/s，尚未验证新反馈能安全接管。选择这些组合会直接报错，不会悄悄改变旧控制器。

## 怎么运行

在 `src/core/run_cubli_clean.m` 中设置：

```matlab
cubliMode = "point_balance";
cubliPreset = "point_near_zero";  % 或 "point_low_speed"
cubliSeconds = 120;              % 可改为 300 观察长时保持
```

然后在仓库根目录执行 `setup_cubli; run_cubli_clean`。入口自动设置并回读模型块的 ODE5 @ 0.125 ms 配置。单独使用 `cubli_mode` 和 `sim` 时也必须设置模型中的 Solver Configuration 块；只改参数结构不会改变已经生成的模型。

独立验收采用**3° 初始扰动**，避免默认 `point_balance` 的 `0.05° / -0.04°` 初值让“几乎没有轮速”显得过于容易：

```matlab
setup_cubli
verify_point_speed("point_low_speed",60,3,0)
verify_point_speed("point_near_zero",120,3,0)
```

验收同时检查顶点高度、真实姿态、三轮合成轮速、每只轮的峰值和接触穿透。`diag_point_speed` 可覆盖初始滚转/俯仰、增益、求解器及局部步长，用于复现下表的对照结果。

## 控制逻辑

顶点控制器从姿态矩阵计算身体对角线的两个水平倾角，与世界系角速度构成二维姿态 PD；偏航使用角速度阻尼。三维目标量通过已辨识的加速度矩阵 `A` 和阻尼伪逆分配给三只轮。本轮只在顶点平衡分支的分配结果后加入比例轮速项：

```text
tau_point = tau_attitude + KwPoint * [wheel_x; wheel_y; wheel_z]
```

这个项使仍在转动的轮继续得到小幅卸速指令，而既有 `KiPoint * integral(wheel_speed)` 保持为零。控制参数另用 `P.run.pointSpeed.ctrl` 输入，不改变历史 58 元素的 `P.run.ctrl` 或任何已有模式码。`point_low_speed` 与 `point_near_zero` 分别给该新输入设置 `3e-5`、`7e-5`；其他预设均为零。

比例反馈降低了转速，但存在非零平台。因此这里的“near zero”是指定测试条件下三轮合成轮速低于 `3 rad/s` 的工程门槛，不表示数学上的渐近零速。偏航方向没有重力恢复力矩，若要把三个轮都严格卸到零，还需要确认接触摩擦可提供足够的外部偏航力矩。

## 开发过程与反例

1. **基线不是零速收敛。**从 3° 滚转起步，旧 `fast` 在 15 s 仍直立，但三轮合成轮速在 ODE3 @ 1 ms 下约 `48.7 rad/s`，在 ODE5 @ 0.125 ms 下约 `87.8 rad/s`。默认小扰动下约零的结果不能代表真实捕获后的卸速能力。
2. **既有轮速积分不能直接照搬。**此前的 `KiPoint` 试验对两种符号和 `1e-4` 起的增益均出现倾覆；本轮不更改该积分项。直接加 `+1e-4 * wheel_speed` 也过强：ODE3 @ 1 ms、15 s 时合成轮速约 `254.6 rad/s`，倾角约 `5.89°`；改成 `-1e-4` 更差，方块落平，三轮合成峰值约 `3128.8 rad/s`。这两条只是方向与量级反例，未纳入预设。
3. **缩小比例反馈后出现可用区间。**`+1e-5` 在 ODE3 @ 1 ms、30 s 末段约 `6.0 rad/s`，120 s 末段约 `0.3 rad/s`；但同增益在 ODE5 @ 0.125 ms、120 s 仍约 `16.215 rad/s`。因此按指定 ODE5 配置继续测试 `2e-5 / 3e-5 / 5e-5 / 7e-5`，60 s 末段分别约 `8.108 / 5.406 / 3.242 / 2.315 rad/s`，同时保持顶点高度与约 `0.001°` 的尾段倾角。
4. **检查方向与长跑。**`7e-5` 对初始 `[滚转,俯仰]=[0°,3°]` 与 `[3°,-3°]` 的 60 s 试验，末段合成轮速均约 `2.315 rad/s`；后者瞬时合成峰值约 `182.5 rad/s`，仍低于每只轮的 `1800 rad/s` 限值。3° 单轴的 300 s 试验，末段仍约 `2.315 rad/s`，质心仍在顶点高度，平面位移约 `6.8 mm`，接触穿透峰值约 `0.37 mm`。
5. **求解器敏感性没有消失。**同一 `7e-5`、3°、60 s，在 ODE5 @ 0.25/0.125/0.0625 ms 下约为 `1.428/2.315/6.121 rad/s`，没有随步长减半而趋于同一个数值。需要继续检查罚函数接触、摩擦和控制输出保持的相互作用，才能提出更强的物理结论。
6. **长时验收曾被日志处理挡住。**第一次运行 120 s 验证脚本时，仿真完成后报告在对已同轴采样的姿态日志重复调用 `interp1` 时耗尽 MATLAB 内存。报告和诊断脚本现在先比较时间轴；相同则直接读取原始矩阵，只在确实错开时插值。修正后相同的 120 s 验证通过，末段合成转速仍为 `2.315 rad/s`。初次正常 JVM 批处理还遇到系统可用虚拟内存不足；本轮后续批量仿真改用 `-nojvm`，不把运行环境失败记作控制失败。

本轮对共享模型做的回归：`verify_cubli` 仍为原有 **6/8 通过**，失败项仍是 `walk` 与 `stand_to_point`；`verify_edge_low_speed("stand_to_edge",30)` 仍通过，捕获约 `1.171 s`、Y 轮末速约 `6.65 rad/s`。以上回归说明这次新增输入没有使原控制路径出现已测到的退化。

## 下一步

- 在其他初始姿态、不同轮速初值和外部扰动下测捕获域，并关注偏航与接触点滑移。
- 找出末段 `2.315 rad/s` 非零平台的来源，建立针对世界系水平动量和偏航动量的独立反馈，而不是继续盲目提高 `KwPoint`。
- 单独研究从棱或平放起立到顶点后的安全接管；必须同时满足捕获、三轮限速和长时卸速，才能扩大新预设的适用模式。
