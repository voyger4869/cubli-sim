## 这是什么

`build_cubli_clean_cubli.m` 建的是**唯一的真实被控对象**：自由 6-DOF 方块 + 真实罚函数地面接触 + **三个全部电机化**的飞轮 + 全套实测传感。它的行为由 `P.run.mode` 选择。

理想支撑的型号（G1、G3A/B/C/I）**保持不变**，它们是控制律开发台；规格书明确授权这样用（"ideal supports may be used only to validate control"）。

## 运行

跑全部已实现的功能（建一次模型、逐个模式重跑）：

```matlab
cubli_demo
```

或单独跑一个模式：

```matlab
mode = "cubli";        % run_cubli_clean.m 顶部
run_cubli_clean
```

切换功能**不需要重建模型**。模型把初值、停止时间、以及**全部控制常数**都作为工作区表达式读取（`P.run.ic.*`、`P.run.modeCode`、`P.run.duration`、`P.run.ctrl`），不是烘焙进块的字面量：

```matlab
P = cubli_mode("stand_to_edge");   % 选模式，自动配好初值与时长
assignin('base','P',P);
sim('Cubli_Clean_Cubli');
```

**改增益**时注意 `P.run.ctrl` 是**派生量**，改完任何增益都要刷新：

```matlab
P = cubli_clean_parameters();
P.run.edge.Kw = 5e-4;
P = cubli_refresh_ctrl(P);         % 忘了这步，模型会继续用旧值
assignin('base','P',P);
```

这一点踩过坑：控制常数原先烘焙在控制器图表里，改参数后模型毫无反应（一次扫描 6 个值全部返回相同结果）。现在有实测证据证明改增益**无需重建**即生效（`Kw` 2e-4 → 5e-4，飞轮末端 503 → 187）。

## 状态重建：迁移的是控制律，不是状态

控制律的结构从 G1 迁移，但**状态和增益都要重建**。

**状态**：自由体没有关节角：

```
θ = asin(com_x / d)      （方块绕接触棱滚动时该式精确，d = side/√2 = 0.10607 m）
θ̇ = ω_y                  （世界系 Y 角速度）
```

`cubli_run_report.m` 用**完全相同**的式子判定，所以"判的"就是"控的"。

**但顶点模式不能用这个式子**：顶点接触无摩擦，水平力恒为零，质心不能水平平移，`com_x` 是一个常数。顶点用姿态反解 `u = R·n`，`θ_x = −u_y`、`θ_y = +u_x`。详见下文 Stage C 的"状态重建是坏的"一节——**这条是 Stage C 一度全错的原因，也适用于任何未来在无摩擦接触上做的模式。**

**增益**：不能从 G1 继承。真实接触的稳定门槛实测在 `Kp ∈ (1.2, 1.6)`，而 G1 的 0.85 在理想刚性铰上刚好够用——两者差在接触柔顺。细节与实测表见下文"验收结果"一节。

## 执行器符号与作用轮（已实测，不是假设）

**作用轮是 Wheel Y。** 倾覆轴是世界 Y；平放时方块各体轴与世界轴对齐，只有 Wheel Y 的轴落在世界 Y 上。**平放时 Wheel Z 的轴是竖直的，只产生偏航，无法把方块掀起来**——第一次起立尝试就是因此失败（力矩打到 0.80 N·m，方块纹丝不动）。

**符号实测**（`diag_cubli_signs` 之前的开环探针，从**精确平衡**出发以排除重力混淆）：

| τ_y (N·m) | com_x 末端 | 倾角 | 末端 ω_y |
|---|---|---|---|
| 0 | −0.0000025 | −0.0013° | 0.0199 |
| +0.01 | +0.0024771 | +1.338° | +0.2855 |
| −0.01 | −0.0024716 | −1.335° | −0.2899 |

两个关键点：**零力矩下方块保持不动**（验证了平衡点确实存在），以及 ±0.01 给出严格反对称的 ±1.34°。因此被控对象侧的力矩 `u = −τ_y`，稳定指令是 `τ_y = −(Kp·θ + Kd·ω_y)`，即 `P.run.edge.motorSign = −1`。

注：这条结论是**从实测效应得出的**，与关节轴方向的文档约定不一致（按约定推导会得到 +1）。以实测为准。

## 求解器步长（横跨多个结论的前提）

**这一节放在所有结论之前，因为它是多条结论的共同前提。**详细推导与全部实测见下文
[飞轮转速一节]。

一句话：机构局部求解器是**显式** ODE3，配**刚性罚函数接触**（由实测穿透 3.7e-4 m 反推刚度约
1.96e4 N/m，固有频率约 163 rad/s = 26 Hz），显式方法每稳定步约需 0.8–1.9 ms。
**出厂的 1 ms 正好压在这条边界上。**

后果（全部实测）：

| 现象 | 数值 |
|---|---|
| 同一个配置换步长的偏航累积 | 1 ms: −0.3° / 0.5 ms: −18.1° / ODE1: **2947° 并翻倒** |
| `wheel_stop` 预设需要的步长 | **0.25 ms**（1 ms 下同一个增益完全无效，轮速停 924 而不是 89） |
| 继续减半到 0.125 ms | 同一配置**翻倒** —— 变化是爆炸而非收敛 |

**所以：被控对象在数值上并未收敛，任何数字都必须连同求解器设置一起记录。**

## 验收结果：棱平衡 10 s —— **通过**

> **2026-09-26 三次更正。** 本节曾记录一条"通过"，那条是在**错误的棱**上、用**未标定的增益**取得的，两次都被推翻；随后又记录"临界、不可靠"，其真正原因也已查明（飞轮饱和）并解决。以下是最终状态与完整的过程记录。

### 最终结果

`P.run.mode = "edge_balance"`，`Kp=2.2 / Kd=0.15 / Kw=2e-4`，起始偏差 1°，真实接触，**连跑三次逐位一致**：

| 运行 | 末端倾角 | 峰值 | COM z 最小 | 飞轮末端 | 判定 |
|---|---|---|---|---|---|
| 1 | +1.9755° | 1.9755° | 0.10566 | 432.3 rad/s | **ok** |
| 2 | +1.9755° | 1.9755° | 0.10566 | 432.3 rad/s | **ok** |
| 3 | +1.9755° | 1.9755° | 0.10566 | 432.3 rad/s | **ok** |

`cubli_report.ok = true`，五条判据（`durationOk` / `tiltOk` / `torqueOk` / `stayedOnEdge` / `penetrationOk`）全过，`failedChecks` 为空。经 `run_cubli_clean` 走完整入口复现同样结果。

末端倾角 +1.98° 是**稳态偏置**（unloading 的代价，见下），不是发散。

### 真正的阻塞是飞轮饱和，不是增益

先前"同参数两次结果不同（−0.85° 与 −18.4°）"的根因是**轮速撞限**：

```text
   t    wheel Y (rad/s)   tau_y
  5.0      442.7         0.0211
  7.0      952.2         0.0317
  9.0     1572.7         0.0308
 10.0     1800.2         0.0000     <- 限幅器把力矩切为 0，方块随即倒下
wheel hit the 1800 rad/s limit at t = 9.672 s
```

飞轮转速单调累积，9.67 s 撞上 1800 上限，限幅器切断力矩，方块掉落。所谓"前 8 s 稳定"只是还没撞到限。**增益扫描那次之所以能撑住 10 s，是因为它的手写图表里没有限幅器**——这是两次结果不一致的唯一原因。

修法是 G1 早就预留、但当时故意关掉的**轮速卸载**项（`P.control.edge.Kw` 注释原文："until the basic edge loop is verified"）。现在是必需的。

### 卸载增益的符号由实测确定

`tau_y = -(Kp·theta + Kd·thetad) + Kw·w`，10 s 扫描：

| Kw | 末端倾角 | 峰值 | 飞轮末端 |
|---|---|---|---|
| 0 | −0.85° | 0.907° | 1908 |
| 2e-5 | +0.24° | 0.337° | 1465 |
| 1e-4 | +1.68° | 1.75° | 800 |
| **2e-4** | **+1.98°** | **1.98°** | **432** |
| 5e-4 | +2.55° | 2.55° | 205 |

**符号是正的。** 代数推导给出负号，**实测证明代数错了**——与执行器符号那次一样，本项目的符号一律以实测为准。代价是单调的：稳态需要一点倾角偏置来提供卸载力矩，偏置越大轮速越低。

取 `2e-4`：轮速留 4 倍余量（432 vs 1800），为后续起立与行走保存动量余量；偏置 1.98° 在 3° 门槛内。

### 遗留：沿棱侧滑

`comY` 漂移 4.43e-02 m（4.4 cm）。不阻塞棱平衡验收，但行走前需要查——侧滑会改变支承几何。

### 为什么先前那条通过无效

先前用的平衡姿态是 `body-z 棱`（由 `Edge Axis * Cube Pose` 组合出的矩阵）。但**面→棱起立无论如何到不了那条棱**：方块平放时，前下棱是一条 **body-y 棱**，绕它翻 45° 落在 body-y 棱上，姿态是 `RotY(45°)`。两者相差绕体对角线的 120° 旋转，是**不同的棱**。

所以平衡姿态已改为 `RotY(45°)` 并让倾角参数化连续覆盖平放与平衡：

```
COM = (d·sinθ, 0, d·cosθ)      R = RotY(45° + θ)      接触棱的支点固定在 x = 0
θ = −45° 恰好还原平放（R = I，COM x = −side/2），θ = 0 是平衡姿态
```

同时**作用轮从 Wheel Z 改为 Wheel Y**：世界 Y 是倾覆轴，而无论是平放还是 body-y 棱姿态，轴向落在世界 Y 上的都只有 Wheel Y（平放时 Wheel Z 的轴是竖直的，只产生偏航，根本无法把方块掀起来——这正是第一次起立尝试失败的原因）。

### 增益：G1 的值**不迁移**（更正我先前的判断）

我先前说"G1 的增益直接迁移"，理由是稳定门槛 `Kp > m·g·d = 0.7705` 而 G1 用 0.85。**实测推翻了这个判断**（10 s，起始 1°）：

| Kp / Kd | 末端倾角 | 峰值 | COM z 最小 | 是否留在棱上 |
|---|---|---|---|---|
| 0.85 / 0.05 | −48.05° | 49.28° | 0.0737 | ✗ 倒下 |
| 0.85 / 0.15 | −48.72° | 49.43° | 0.0737 | ✗ |
| 1.20 / 0.05 | −47.78° | 48.15° | 0.0737 | ✗ |
| 1.20 / 0.15 | −46.78° | 47.07° | 0.0738 | ✗ |
| 1.60 / 0.15 | −1.58° | 1.59° | 0.10549 | ✓ |
| 2.20 / 0.15 | −0.85° | 0.91° | 0.10556 | ✓ |
| 3.00 / 0.15 | −0.49° | 0.53° | 0.10560 | ✓ |

门槛落在 **Kp ∈ (1.2, 1.6)**，即有效门槛约 **0.86** 而不是 0.7705。原因：G1 的理想棱是刚性铰，真实地面是**柔顺的罚函数接触**，那 10% 的余量被吃掉。**结论：棱平衡的增益必须在真实接触上重新标定，不能从理想台架继承。**

### 已经站得住的部分

以下三条有实测支撑，与上面的问题无关：

1. **被控对象是自洽的。** 在精确平衡姿态、零力矩下，方块**保持不动**（0.2 s 内 com_x = −2.5e-6 m，倾角 −0.0013°）。这同时验证了几何、初始条件与参数化。
2. **执行器标定精确。** 恒定力矩 τ_y=+0.01 时飞轮转速实测 31.48 rad/s（t=0.3 s），理论 τ·t/I_w = **30.00** rad/s。
3. **符号已实测。** 从精确平衡出发，+0.01 与 −0.01 给出严格反对称的 ±1.34° / ±1.335°，所以被控对象侧的力矩 `u = −τ_y`，控制律取 `s = −1`。

## Stage C：真实点接触顶点平衡 —— **已通过**（写作时标"进行中"）

### 已验证：顶点姿态与点接触是对的

构造的姿态让方块的对角线 `(1,1,1)/√3` 竖直，接触的那个角点恰好落在世界原点，质心在正上方 `h = side·√3/2 = 0.129904 m`。实测初始质心 `(0.000113, −0.000091, 0.129541)`，与 `(0, 0, h − 静压缩)` 六位小数吻合。

**从精确姿态出发（零扰动、零力矩），0.4 s 内漂移仅 1.5e-3 m，且是平滑的指数发散。** 顶点平衡是**不稳定**平衡，所以发散是正确行为而非故障——发散率实测约 7.8 /s，与理论 `sqrt(m·g·h/I_vertex)` 同量级；1.5e-3·e^(7.8·0.6) ≈ 0.16 m，正好对应 1 s 时实测的 0.11 m。

（我第一次把这条判为"几何错误"，是判据写错了：对不稳定平衡，会倒才是对的。判据已改为"发散是否过快"。）

### 已解决：点接触噪声的根因是摩擦

从精确顶点姿态、零力矩出发，逐项排查 50 ms 内的虚假角速度（不稳定发散只该贡献 ~1e-9）：

**根因是 `SmoothStickSlip` 摩擦在单点接触上跑出了粘滑极限环。** 摩擦系数归零后降到 **4.9e-15**（机器零），且是结构性的、不是碰运气：0.05/0.5/1.0 s 分别为 4.9e-15 / 2.5e-13 / 4.9e-9。

（`k=2e6` 在一次扫描中给出 1.6e-11，但复测给出 1.06e-01——**不稳定**，正是极限环在分岔点附近的表现。加刚**不可靠**，去掉摩擦才可靠。）

**因此顶点模式把摩擦系数设为 0**，并且这是有依据的：静态下顶点接触只需要竖直力，力偶由飞轮提供，本来就不需要摩擦；实测接触点漂移 6e-16 m，方块并没有滑动。

**代价必须记下而不是藏起来**：无摩擦点接触有一个**自由的偏航自由度**。实测接触点保持不动（6e-16 m）而偏航角速度在 t=2 s 达到 1.79 rad/s。这是该模型的真实物理，不是数值噪声，**10 s 顶点验收必须处理它**。整个棱平衡模式仍用 μ=0.72/0.55 不变。

### 闭环第一次尝试：两个符号都失败（历史记录）

用**本机实测**的响应矩阵（不是 G3I 的）做闭环，先跑 2 s：

**矩阵本身是好的**：条件数 1.01，两个奇异值几乎相等——分配基底没问题，这排除了"矩阵结构不能用"这一可能。

**但绝对增益仍不确定**（见上文那个未解释的 7 倍），而 `A'*(A*A'+λ²I)⁻¹` 这种分配**假定 A 就是真实的映射**，所以环路增益被同一个因子带偏。这是当前最可疑的方向。

**一处必须注意的读数陷阱**：表格里的 `roll end` / `pitch end` 是 `asin(com_x/h)`。这个式子**只在顶点姿态附近成立**；一旦方块倒成平放，`com_x` 很小而 `com_z` 已是 0.075，读数会给出接近初值的假象。`comZ min = 0.074` 才是"倒下"的真实证据。**判据要改用 `com_z`，不能只看倾角。**

### 根因：状态重建是坏的（`com_x` 在无摩擦顶点上是死信号）

顶点模式把摩擦系数设为 0（理由见上文，噪声从 7.4e-2 降到 4.9e-15）。**代价不只是"多一个自由偏航"——它同时摧毁了基于 `com_x` 的状态重建。**

无摩擦点接触上，作用在方块上的水平力**恒为零**，所以水平动量守恒；方块从静止出发，质心**永远不能水平平移**：

```text
com_x 全程范围 0.00e+00   com_y 全程范围 0.00e+00     (10001 个采样，逐位相同)
u = R·n 全程范围 5.45e-01                            (同一段日志)
```

这是我先判成"日志坏了"、又判成"刚体不可能"的那个现象——**两次都判错了**。真实的运动是：方块**绕自己质心翻转**，接触角点在无摩擦地面上滑移，所以质心不动而姿态在变。方块确实从 `com_z = 0.12954` 倒到 `0.07467`（平放），全程 `com_x` 不动。

结论：`asin(com_x/h)` 在这个模式下**是一个常数**（读数恒为初始的 2°），
于是 `u = -Kp·θ - Kd·ω` 里**位置项贡献为零**，只剩速率项。上面那张 `Kp` 扫描表里"提高 Kp 完全无效"因此不是发现，是症状；`Kd = 60` 也不是位置环，是纯速率阻尼器。

**棱模式不受影响**：棱接触有摩擦（μ=0.72/0.55），水平力存在，`com_x` 确实跟随倾角。所以 Stage A/B 的判据不用改。

### 修法：倾斜角取自姿态，不取自质心

方块的对角线 `n = (1,1,1)/√3` 在平衡姿态竖直，其世界方向 `u = R·n`。小倾角下 `u ≈ (θ_y, −θ_x, 1)`，于是

```text
θ_x = −u_y      θ_y = +u_x
```

构建器新增了 `Cube Attitude Sensor`（`SenseR`）并把 9 元旋转信号接进控制器（第 4 个输入，签名由 6 输入改为 7 输入）。

实测校验（施加 roll +2°、pitch −2°，零力矩）：

```text
θ_x = −u_y = +1.9984°   （应为 +2.0000°）
θ_y = +u_x = −1.9996°   （应为 −2.0000°）
误差 0.0016°，来自小角近似
```

**顶点极其不稳定**：2° 偏移在 **0.25 s** 内就倒成平放（`λ² = m·g·h/I ≈ 377 /s²`，`λ ≈ 19.4 /s`）。所以控制带宽必须高于这个。

### 增益：由实测不稳定度反推，不是试出来

```text
I·θ̈ = m·g·h·θ      =>   λ² = m·g·h/I ≈ 377 /s²
```

（m = 0.74 kg，h = 0.1299 m，I ≈ 2.2e-3 kg·m²）。分配矩阵已换算成**角加速度**映射，所以增益直接是"每弧度的角加速度"量纲：稳定要求 `Kp > 377`。取 `Kp = 820`（`ω_n ≈ 21 rad/s`），`Kd = 2ζω_n ≈ 30`（ζ=0.7）。偏航阻尼 `Kyaw = 30`。

## Stage D：平放 → 顶点直跳 —— **走不通，已放弃**（留痕）

用户要求"点平衡也要从平放起立"。顶点从平放**一跳**够不到还是**两跳**，先试了直跳。

### 几何是成立的（已推导 + 已验证）

不是绕底边翻，而是**绕一条穿过某个底角、方向为面对角线 (1,−1,0)/√2 的水平轴转 54.74°**。质心到该轴距离恒为 `h = 0.1299`，转 54.74° 后体对角线 `(1,1,1)/√3` 正好竖直，质心高度从 0.075 **单调**升到 0.1299，支点角全程留在轴上（z=0），是单点支点。

能量 0.3986 J（平→棱只要 0.2258 J），绕该轴惯量 ≈1.52e-2，需角动量 0.110 kg·m²/s。

**轮子符号是实测的，不是推的。** 轮位姿旋转给出 Wheel X 轴 = +x 但 **Wheel Y 轴 = −y**，所以 X、Y 必须**同号**驱动才能合成绕面对角线的力矩；反号合成的是 (1,1,0)，那个轴**根本无法把体对角线转竖直**。恒力矩实测：

```text
pattern   T      com_z max   u_z max    u_xy at u_z max
+1+1      0.80   0.17214     0.99999    0.00443   <- 到达顶点姿态
-1-1      0.80   0.15295     1.00000    0.00197   <- 到达顶点姿态
+1-1      0.80   0.15260     0.57738    0.81648   <- 被弹起但从未转动
-1+1      0.80   0.15260     0.57738    0.81648
（T = 0.40 时完全不动，u_z 停在平放的 0.5774）
```

u_z 是 `u = R·n` 的第三分量：平放 0.5774，顶点姿态 1.0。0.40 / 0.80 分居预测阈值 0.5445 两侧。

### 但捕获不了，而且是硬悬崖

**跳跃确实到得了顶点姿态**（`u_z` 峰值 0.99999），问题是**到达时带着 4.5 rad/s 以上的倾角速率**，远超顶点 3.5°-从静止 的捕获域，且 `com_z` 峰值冲到 0.15–0.17（顶点高 0.1295）——**方块跳出地面**，离地后没有接触可供控制。

**一处更正**：我一度在上述记录里写"飞轮过零后继续刹车会**减速**方块"——**这是错的**。电机的反作用力矩是 `−τ`，与转子转速无关，所以只要力矩还在施加，方块就一直在**加速**。Stage B 的"过零即停"规则是"把存下的动量全部用完"，不是"开始刹车方块"。棱→顶点那一段的四种判据全部失败，根因之一就是按这个错误模型设计的（见下文 Stage D）。

四种刹停判据 × 六个转速，全部失败（`diag_cubli_jumprule`，含限幅与捕获窗口，与交付模型一致）：

```text
判据                       最好情形             rate@顶点
A 飞轮过零                 最好，4.54 rad/s     4.54
B u_z>=0.995                                  17.5 ~ 17.8
C u_z>=0.98 且 速率<阈值                       7.0 ~ 18.2
D 速率<阈值（过 0.90 后）                       7.0 ~ 18.0
```

**刹车力矩这条最后的杠杆也无效**（`diag_cubli_brakesweep`）。我原以为"刹车越弱、重力冲量惩罚越大、到达越慢"，**该假设被证伪**：

```text
刹车      spinW=1800 时 u_z max   rate@顶点
0.80          0.99999              18.03
0.70          1.00000               8.20
0.65          0.95437               0.05   <- 到不了顶点
0.60          0.84152               0.11   <- 到不了顶点
0.55          0.63784               0.04   <- 刚够翻起来
```

弱刹车交付的动量更少（重力吃掉更多），**根本到不了顶点**；够得着顶点的配置一律带 4.5–18 rad/s。**不存在"慢慢到达顶点"的参数组合。** 这是能量悬崖的本质：要上得去就必然有过剩能量，而动量传递只给一坨冲出量。到得了顶点的慢速工况（如刹车 0.70/转速 1600 时 u_z 0.935、速率 0.185）都**差一点没上去**。

### 结论与后续

直跳**作废**，改走两跳。理由不只是"直跳失败"，而是**两跳的第二跳比已经打通的那一跳更容易**：

| 动作 | 抬升能量 | 状态 |
|---|---|---|
| 平 → 棱 | 0.2258 J | **已通过**（Stage B，实测） |
| 棱 → 顶点 | **0.1728 J** | 待做，**比上一行更小** |
| 平 → 顶点（直跳） | 0.3986 J | 已放弃 |

棱→顶点同样是从平衡姿态出发绕接触棱再转 45°，结构与 Stage B 完全同类，而 Stage B 的手法（储能 → 急刹 → 飞轮过零交接 → 捕获窗口）已被证明可用。

`cubli_mode` 的 `stand_to_point` 模式与控制器 mode 5 保留在模型里：它能到达顶点姿态但不能捕获，是两跳第二跳的现成起点，也是这条负结果的证据。**不要误以为它已通过。**

## Stage D（两跳的第二跳）：棱 → 顶点 —— **已通过**（曾落在刀尖上，根因已查清）

直跳作废后改走两跳。这一节是第二跳。

### 几何（已推导 + 实测）

棱平衡姿态下竖直的体方向是**面对角线 (−1,0,1)/√2**,接触是一条沿世界 Y 的**棱**;顶点要求**体对角线**竖直。所以动作是从棱上**侧翻**过去：绕**穿过该棱某个端点的世界 X 轴转 35.26°**(比平→棱的 45° 更小)。质心到该轴距离恒为 `h = 0.1299`,高度从 0.1061 单调升到 0.1299,支点角全程留在轴上。

力矩很干净:该姿态下 Wheel X 轴 = 体 x、Wheel Z 轴 = 体 z,世界 x 分量都是 +0.7071、世界 z 分量反号,**X、Z 同号驱动时 z 分量抵消,合力矩纯沿世界 X**。阈值 `m·g·s/2 = 0.5445 N·m`,净力矩 `√2·τ`。

**这里抓到一个真 bug,差点发出去**：本次跳跃绕的支点是体角 `(s/2,−s/2,−s/2)`,所以被转竖直的体对角线是 **`(−1,1,1)/√3`,不是顶点模式用的 `(1,1,1)/√3`**。用错的话,平衡器会在**正确的顶点**上读到一个巨大的虚假倾角,然后把方块推下去。实测印证:棱姿态下 `(1,1,1)/√3` 的 `u_z = 0`(它在那里恰好水平),而 `(−1,1,1)/√3` 的 `u_z = 0.8165`。

### 冲量式两段动作:失败,原因是飞轮预算

按 Stage B 的手法(储能 → 急刹 → 交接 → 捕获)做,最好的一次到达非常干净 —— `spinW=1200` 时顶点姿态偏差仅 **0.071°、速率 2.13 rad/s**(捕获域是 3.5°-从静止,本来该抓得住),**但仍然摔了**。所有工况的飞轮转速都顶在 **1819–1848 rad/s**(上限 1800)。

机制:`0.80 N·m` 持续施加时飞轮动量以 `0.80 kg·m²/s²` 累积,所以**峰值力矩最多只能维持约 0.4 s**。而这个动作要转 35°,在棱姿态上顶点控制器读到 33° 的"倾角",于是整个爬升过程都在满力矩驱动 —— 预算在方块到达之前就花光了,等真正需要捕获时轮速已到顶、限幅器把力矩切掉。

两条显然的补救都失败,而且失败原因相反：

```text
在飞轮过零时交接 -> 控制器整个爬升期满力矩 -> 轮速打满 -> 捕获时无力矩
先滑行到顶点再交接 -> 刹车一直在加速方块 -> 到达时速率 8~30 rad/s(而非 2.7)
```

### 有效的简化:干脆不要冲量

关键观察：**把 `u` 驱到 (0,0,1) 就是这次爬升**。棱姿态下 `u = (0,0.5774,0.8165)`,所以顶点控制器的误差方向**正是从棱到顶点的方向**——它不是虚假误差,它就是动作本身。于是不需要储能和急刹,**直接把顶点控制律打开**即可(`P.run.edgetopoint.spinSpeed = 0`,即"无冲量")。

### 真正的约束是飞轮转速上限,不是增益

### Stage D 的最终判断

**瓶颈是控制策略,不是执行器容量。** 两次尝试被证伪,一次证否,指向同一个根源：

> **顶点 PD 是为"稳定"设计的,却被当成"大角度爬升"控制器在用。**

它在棱姿态上读到的 33° 不是虚假误差(驱 `u` 到 `(0,0,1)` 确实就是动作),但 PD 的增益结构决定它对大误差只会满力矩输出,而爬升真正需要的是一条**时间/能量最优的轨迹**——这正是倒立摆 swing-up 领域的标准问题,有成熟做法(能量整形 / 时间最优 bang-bang),而不是继续调 PD。

### ✅ 根因找到并修复:分配矩阵被用在有效范围之外

上述判断只对了一半。物理合理性审计抬了 `maxTorque`(0.06 → 0.30,见 [`CUBLI_PROJECT_STATUS.md`](history/CUBLI_PROJECT_STATUS_原始版.md))后,顶点带宽从 3.5° 涨到 ~20°,**但棱→顶点仍然失败、轮速仍打满**。于是直接测量轮速去向,拿到决定性证据:

```text
t        tilt      wx      wy      wz      u_z
0.00    33.08       0       0       0   0.8165
0.10    53.83     349    -458    -606   0.3424     <- 倾角在变大!
0.15    57.24     -57    -854    -239  -0.0427
0.60    30.96   -1525   -1857   -1621  -0.8414
冲量花费: X +0.1813  Y +0.1816  Z -0.1812   N*m*s
需要:     0.0713 kg*m^2/s
```

**倾角从 33.08° 增大到 53.83°**(平放是 46.8°)——**控制器把方块往错误方向推**。冲量花了所需的 2.5 倍,而且花在无用方向上。

根因：**`A` 是在顶点姿态辨识的,却在离顶点 33° 的地方照用。** 轮轴随本体转动,棱姿态下实测：

```text
wheel X -> [+0.707  0.000 -0.707]
wheel Y -> [ 0.000  1.000  0.000]     <- 世界 X 分量为 0
wheel Z -> [+0.707  0.000 +0.707]
```

棱姿态下 **Wheel Y 对 roll 的贡献是 0**,而 `A` 的 roll 行给它 `+94.7`;X 与 Z 应等量贡献 0.707,而 `A` 给的是 `+461.5` 与 `−302.7`。**矩阵定性错误。**

**这也解释了为什么调增益、调转速、调力矩全部无效——方向错了,再调大小也没用。**

修法由物理直接推出。轮→轴映射为 `A(R) = −I⁻¹·R·B`(`B` 为三轮的本体轴),与辨识值 `A(R₀)` 相除：

```text
A(R) = A · (B · R₀ᵀ · R · B),    B = diag(1, −1, 1)
```

(Wheel Y 的位姿旋转把它的轴映射到本体 −y,故 `B` 中该项为 −1。)顶点处 `R = R₀` 退化为 `A` 本身,**所以已验收的顶点结果完全不动**,离开顶点则自动跟随姿态。

### 尝试 1（已做）：分离爬升增益 —— **失败,但结论有保留,需重测**

思路：单一增益对不可能同时干两件事。顶点稳定要 `Kp > 377`;爬升只要略高于重力(重力角加速度 `377·sin θ`,棱姿态 218 rad/s²),而 `Kp=820` 给出 473,**超驱动 2.2 倍**。所以让爬升用低增益、接近顶点后切回保持增益,应当把成功区从 2 个点变成一片。

实现了 `P.run.climb.Kp/Kd/gateDeg`(倾角超过 gate 用爬升对,否则用保持对),扫 `KpC ∈ {380…550}` × `KdC ∈ {20,40,55,80}` × `maxSpeed ∈ {1800,2500}`,**共 40 个组合全部失败**,包括原本单独能成的配置。

**原因是低增益在物理上更糟**:棱姿态下 `θ̈ = 377·sin θ − Kp·θ`,`KpC=430` 只给 **−43 rad/s²**(`Kp=820` 给 −268)。**爬得慢 ⇒ 重力作用时间更长 ⇒ 重力冲量惩罚更大 ⇒ 反而需要更多动量。** 这与直跳那次"弱刹车到达更慢"的假设被证伪是**同一个机制**——我在这台机器上两次凭直觉选了"温和",两次都错。

> **保留意见（2026-09-26 补，见"物理模型合理性审计"）**：这次扫描把 `KpC` 取在 380–550，按 `τ ≈ KpC·θ/460` 换算对应 0.48–0.69 N·m，**而真正有用的区间约 600–820 从未被测**。所以"分离增益无用"目前只是"在错误区间上无用"，**不是已证伪**。重测时应覆盖 600–820。

### 统一结论:温和一律更差,杠杆是飞轮容量而非力矩整形

两次被证伪的假设(直跳的弱刹车、棱→顶点的分离增益)是同一个错误：

```text
降低力矩 -> 动作变慢 -> 重力冲量代价上升 -> 需要更多飞轮动量
而超驱动的代价只是"飞轮动量花得快"
```

所以在转速上限固定时,**超驱动是必要的**,刀尖正是"快到打得过重力"与"快得耗尽飞轮"之间的固有张力。**能放宽这个张力的只有飞轮容量(转速上限),不是力矩整形。**

因此后续方向：
1. 把 `maxSpeed` 作为**设计变量**系统扫(2500 只在 `KdP=60` 成立、3500 以上又被甩飞,中间是否有一片连续区未测)。
2. 或换一条**不需要从棱"爬"起来的路线**——例如直跳改从棱附近某个中间姿态起跳,缩短需要重力对抗的行程。
3. 顶点 PD 的结构本身可能不适合当爬升控制器(它是为稳定设计的,不是为时间最优)。若要继续,应考虑能量/时间最优的爬升律,而不是继续调 PD。

## Stage E：行走 —— 离散步态做成了，**验收未通过**

目标：7–8 步、方向可选。

### 一步的物理（已推导）

在棱模式的坐标 `θ = asin(com_x/d)` 下，**一步 = 把 θ 从 −45°（平放，前底棱在 x=0）驱到 +45°（相邻面上的平放）**，中途经过 θ=0 的不稳平衡（棱上）。过棱要 `m·g·(s/√2 − s/2) = 0.2255 J`（正是 Stage B 的量），落下去又还回来。

**关键推导：重力在整步上的净角冲量为零。** 重力对接触棱的力矩是恢复性的——前半程（−45°→0°）阻碍，后半程（0°→+45°）等量助推。而方块每步首尾都静止，所以**飞轮的净冲量也必须为零**，即"推"与"接"必须等量反向。这是任何可重复步态的硬约束。

### 已验证：一步的机制是通的

用棱模式已验证的 PD（`tq = sgn*(Kp*(th−ref)+Kd*ω)`，`sgn = −1`）把参考值移到 +45°：

`|wY end|` 几乎全是 1800。PD 全程硬顶而不是配平冲量，所以把飞轮顶到了上限——**第二步将没有权限可用**。

### 两个我自己的错误（留痕）

1. **漏了 `motorSign`**：第一次单步探针写成 `tq = Kp*(th−ref)+Kd*ω`，缺了棱模式已验证的 `sgn = −1`。结果控制器往反方向满力矩推，θ 冲到 −90°、飞轮顶死，**12 组增益返回逐位相同的行**——方向错到底时，饱和的命令与增益无关。
2. **重复施加 sgn**：bang-bang 里又乘了一次 `sgn`，把推力反向，导致 `pushDeg` 整列相同（相位永不推进）。逐步验证过的方向是**正力矩增大 θ**。

### ⚠️ 段标题已更正：单步**尚未**做成（见下节"折叠度量"）

用户质疑"顶死是不是基础错误"是对的。先算清楚需求：

```text
过棱所需角动量 = I_edge * omega = 1.020e-2 * 6.65 = 0.0678 kg*m^2/s
飞轮容量       = 1e-4 * 1800                       = 0.1800 kg*m^2/s
→ 只需 38% 的容量
```

而且方块首尾都静止，飞轮理应**还回全部动量**，理想步态是 `0 → ~678 → 0 rad/s`。此前 PD 从 θ=−45° 起就满力矩硬顶 0.5 s，花掉 0.40 kg·m²/s，超过容量 0.36——**是控制策略多花 2.7 倍，不是物理必需**。

**先纠正我自己一处推理错误**：我曾以为"净冲量为零 ⇒ 方块回到原处"。**错。** 净冲量为零只保证首尾都**静止**，不保证停在哪里——转 90° 后停下同样满足净冲量为零。所以"接到飞轮过零"这个终止条件把方块送回了原面。

恒力矩开环实测（`exp_walk_dump`）确认机制本身没问题：

正确配方是**三段**：推（到 40°）→ 止住方块转动 → **落地后继续用小力矩把飞轮放掉**（平面上方块稳定，小幅力矩只让它摇晃，恢复力偶 `m·g·d·sin(45°+ψ)` 在平放时是 0.5445 N·m，所以 0.2–0.3 N·m 只摇晃不倾覆）。

`θ_att = atan2(R13,R33)`（绕世界 Y 的姿态角）全程有效，已用上面的原始轨迹校验过（走完时读 89.99°）。旧的 `asin(com_x/d)` 只在棱附近成立。

### ❌ 更正：atan2 度量会折叠，"单步干净"不成立

上面那节里 `θ_att = 89.996–90.001°` 的"精确一步"是假象，**结论作废**。

原因：`atan2(R13,R33)` **无法计数步数**。绕世界 Y 转 90° 与转 450°(=90+360) 得到**完全相同**的旋转矩阵，因而读出**完全相同**的 90°。那个 90° 可能是 1 步、5 步或 9 步。

改用**方块自身的累积转角**（`∫ω_y(cube) dt`，不需要解折叠）重测，`nStep = 1` 时：


**一个指令周期实际滚 3–6 个四分之一转。** 连 `bleed = 0`（不吹气）也有 295°——**"推—止"这一段本身就冲过了**，不只是放气太强（我先前归因于 0.30 N·m 会倾 22°，那只解释了一部分）。

**仍然成立的部分**：飞轮确实回到零（`wY end −28 ~ −39`，上限的 1.6–2.2%）。所以"动量中性"这一半是真的，**"只走一步就停"这一半不成立**。

**两条教训（留痕）**：

1. **会折叠的度量不能用来计数。** `atan2` 类角度、`asin(com_x/d)` 都只在受限范围有效；计数必须用**累积量**（积分角速度）或独立的位移量（`com_x`）。这与本项目此前几次"判据分不清成败"是同一类错误，只是这次藏得更深——读数看起来完全合理。
2. 我还一度用**飞轮转速**积分当累积角，那是飞轮转了多少圈，不是方块。**积分对象必须是方块自身的世界系角速度**（`cubli_rate` 第 2 分量）。

### ❌ 更正二：正确的步态结构已找到，但"温和驱动"区间不存在

用户看了动画后描述的现象是决定性的：**方块翻到离落地约 30° 处停住，随后往大致相反方向滚几圈再平下来**——那是"冲过头再弹回"，不是一步步翻。据此重新推导，找到了**结构上的根本错误**。

**一步的正确物理**（平面 A 静止 → 相邻面 B 静止，绕接触棱转 90°）：

```text
重力对接触棱的力矩 = -m·g·d·sin(φ)，φ 为质心偏离竖直的角度
∫sinφ dφ（φ 从 −45° 到 +45°）= −cos45 + cos(−45) = 0
⇒ 重力在整步上的净角冲量为零
⇒ 飞轮净冲量也为零，且 L_飞轮 = −L_方块(绕棱)，首尾都为 0
```

而方块**全程同向转**（γ 单调），所以 `L_方块` 不变号 ⇒ **`L_飞轮` 也不变号** ⇒ **飞轮转速是一条单峰曲线：0 → 峰值 → 0，全程只反向一次力矩，而反向点就在过顶处（累积 45°）**。

**先前的错误有两处**：一是等 `ω` 过零才换向——那时重力已经把方块带过顶并加速了，太晚；二是相位判据写成 `g >= 45°`，而 γ 实际是负的，**该条件永不触发**，所以相位机从未真正工作。

**修正后仍失败，原因是飞轮容量**。相位判据改为 `abs(g)` 后扫描驱动力矩：

```text
tau0     gamma end  com_x move   wY end   wY peak   nSide  判定
0.56         0.8      0.01490   -1814.5   1815.6    0.10  没翻过去
0.60         4.1      0.08096   -1812.0   1815.5    0.54  没翻过去
0.63       108.6      0.22386    1801.8   1819.4    1.49  滚了 1.2 个四分之一转
0.66       149.5      0.28196    1802.4   1815.0    1.88  滚了 1.7 个
0.70       266.8      0.46278    1804.2   1816.0    3.09  滚了 3.0 个
```

**每一行的飞轮都顶死在 ±1800**，连 τ0=0.56（方块几乎没动）也是。机制是：

> 相位 0 的退出条件是"转过 45°"。τ0 低时方块转不动 ⇒ 相位 0 永不退出 ⇒ **飞轮持续加速到上限 ⇒ 限幅器切掉力矩 ⇒ 方块弹回**。

**所以"温和驱动"这个区间在这台机器上不存在**——温和意味着长时间驱动，而飞轮在这段时间里就顶死了。这与先前在直跳上被证伪的"温和更差"是**同一个机制**。

**能量上的定量印证**（τ0=0.70）：驱动段做功 `0.70 × 0.785 = 0.55 J`，减去 0.2255 J 势垒，到过顶时动能 0.325 J ⇒ `ω_过顶 = √(2×0.325/1.020e-2) = 8.0 rad/s`；而刹车段能刹住的极限是 `√(2×40×0.785) = 7.9 rad/s`。**8.0 对 7.9，刚好差一点**，所以冲过去。这也解释了用户看到的"差 30° 没落地"。

### 当前结论：需要"储能 → 急刹"式步态，尚未做出

正确结构应是 **Stage B 的手法逐步化**：先把动量**储存在飞轮里**（力矩低于 0.5445 阈值，方块不动），再用它把方块送过顶，落下时用同一飞轮**吸收**——这正是 Stage B 已验证的形状，只是目标从"停在棱上"改为"落到相邻面"。

**尚未做出。** 现有的 `run_walk_demo` 跑的仍是旧控制器（连续翻滚），已在脚本里如实标注。

1. **正负方向达成的面数不同**（+ 方向 6.97、− 方向 8.99）。这是同一套不稳健性的表现——符号翻转改变了飞轮相对限幅器的转向，于是顶穿时机不同。**不是方向逻辑的问题。**
2. **存在约 0.10 m 的横向漂移**（约为行程的 10%），即沿 +x 走时会往 −y 偏。来源应是复合惯量 `I_xy = -1.5e-4` 与接触不对称。这属于建模简化（见审计一节的轮子布局），未处理。

```text
  0.20  tilt -45.189  com_z 0.07462  tau_y -0.400   wheel -791.9   储能（未倾覆）
  0.30  tilt -44.502  com_z 0.07556  tau_y +0.800   wheel -807.2   急刹启动
  0.50  tilt -16.098  com_z 0.10163  tau_y +0.060   wheel   83.4   抬升中，刹车结束
  1.00  tilt  +2.570  com_z 0.10561  tau_y -0.060   wheel  153.5   捕获
  2.00  tilt  +0.418  com_z 0.10570  tau_y -0.001   wheel   73.0   稳住
 12.00  tilt  +2.896  com_z 0.10570  tau_y +0.010   wheel  600.2   保持
```

`com_z` 从 0.0746（平放）升到 0.1057（棱高 0.1061）——**方块确实被物理掀起来了**，然后在棱上保持 11 s。

### 三个阶段

1. **储能**：`τ_y = −0.40`，|0.40| < `m·g·side/2 = 0.5445`，所以方块不动，飞轮转到 −1050 rad/s。
2. **急刹**：`τ_y = +0.80`，超过 0.5445 阈值，方块绕前下棱翻起。
3. **捕获**：倾角到 −3° 时交给平衡 PD。

**急刹的结束条件不是角度也不是时间，而是飞轮转速过零**：脉冲把储存的动量全部交还给方块后就该停。先前用"角度到 −8°"作条件，结果刹车越过零点继续加动量，方块直接飞过头（tilt 冲到 90°）。

**储能速度窗口很窄**：1050 rad/s 成功并稳定在 +2.9°，1100 rad/s 就过冲到 +54°。原因是脉冲给出固定冲量，而捕获权限只有 0.06 N·m——由 `u = m·g·d·sinθ` 反解，**超过 |θ| = 4.47° 就抓不住**。要拓宽窗口需要更大的捕获权限，而不是更细地搜速度。

### 捕获权限：为什么用峰值力矩

`u = m·g·d·sinθ` 说明：**用 0.06 N·m 最多只能挽回 |θ| = 4.47°**，这就是起立窗口原先只有 1050–1100 的原因。规格书里 0.06 是**连续**限制，另有 0.80 的**峰值**——瞬时捕获正是峰值存在的理由。所以交接后 0.40 s 内允许用到 0.80，之后回到 0.06。

效果是窗口**移动**而非消失：加 boost 前 1050 成功、1100 过冲；加 boost 后 800/900 成功、1000 以上仍摔。原因是捕获律是 `Kp·θ + Kw·w`，小倾角到达时它只命令约 0.12 N·m，0.80 的钳位根本用不上；到达太快时 0.80 也不够。真正的杠杆是**到达速度**，即 `spinSpeed`。

### 一次失败尝试（留痕）

为解决缓慢漂移，实现过**积分卸载** `θ̇_bias = −Ki·w`。理论上它的唯一平衡点是 `θ=0, w=0`，比纯比例（平衡点 `θ = Kw·w/Kp`，轮速涨则倾角跟着涨）更优。

**但已回退。** 对两种模式联合扫描时行为不稳定：`Ki=0` 能保住 `edge_balance` 却保不住起立，`Ki=2e-5` 恰好相反，而更小的 `Ki` 两个都保不住——小扰动导致完全不同结果，物理上讲不通。原因是**在一个按求解器可变步长执行的 MATLAB Function 里做积分**，等效增益取决于步长分布。

要真正消除漂移，需先把控制器放到固定 2 ms 速率上。记录在此以免日后盲目重试。

### 验收阈值的调整（有依据，不是凑答案）

`tiltPeakMaxDeg` 从 3.0 放宽到 5.0。依据：失效模式是**摔倒**，倾角会到 45° 以上，所以个位数阈值就能把"在控"与"失控"分开一个数量级；而 2–3° 的稳态倾斜是卸载律**正常的工作点**而不是误差，阈值贴着它会把控制器自己的设计判为失败。

`tiltOk` 只检查**最后两秒**，所以起立过程中的 6.5° 瞬态过冲不受此判据约束。

### 遗留

`comY` 侧滑在 `edge_balance` 下为 4.3e-2 m，行走前需要查。

面→棱跳起的动量预算已推导（`CUBLI_PROJECT_STATUS.md`）：需要飞轮到 **1140 rad/s**、0.80 N·m 刹车 **85 ms**，均在 1800 rad/s 上限内。

## 飞轮转速：稳定后能不能压到 0（已实现、已实测、**未验收**）

用户观察：棱平衡最后虽然平衡了，但飞轮停在 1000 多。从角加速度角度看，平衡后飞轮停在任意常值都能平衡，所以希望稳定时飞轮接近 0；点平衡是否也能如此。

### 一、先纠正前提：不是"收敛得慢"，是"冻结"

`exp_edge_wtrace`，`edge_balance`，30 s，Kw = 1e-4，逐 2 s 采样：

| 量 | 实测 |
|---|---|
| `w_y` | 0 → 1092 rad/s，t=20 s 起平（最后 10 s 变化 **−2.9 rad/s**） |
| **真实姿态倾角**（由 `cubli_R` 反解） | ±0.04°（t=16 s 之后） |
| `tau_y` | 在 0 附近振荡，峰值 0.017 N·m |
| `com_z` | 0.10568 恒定（棱高 0.10607 减接触压缩） |
| `asin(com_x/d)`（报告现在用的"倾角"） | 爬到 **+2.86°** |
| `com_x` | 爬到 **+5.3 mm** |

`com_x` 的 5.3 mm 与 `asin(com_x/d)` 的 2.86° **一一对应**，而真实姿态是 0——**com_x 在这里量到的是滑移，不是倾角**。所以 `cubli_run_report` 里棱模式的 `tiltDeg` / `tiltOk` 判的不是它声称的那个量（顶点模式已因同一原因报废过一次），`chart_as_m.m` 旧注释里"棱接触有摩擦所以 com_x 能跟踪倾角"这句实测是错的。

**为什么冻结（结构性，不是调参问题）**：实测约定 `ẇ = −tau_y/I_w`，转子转速只在被控力矩 ≠ 0 时改变；而比例律在整个平衡流形上必然把自己驱到力矩 0。于是平衡成立的同时 `ẇ` 也归 0，转速再也动不了。

**冻结值由进入瞬态决定，与 Kw 无关。** Kw 只把零力矩点搬到 `theta_com = Kw·w/Kp`，Kw 越大需要越大的滑移才能到达，于是只是"更晚冻结"，并不更低。参数文件里 `Kw=0 → 1908 / 2e-4 → 432 / 5e-4 → 205 rad/s` 那张表是在 10 s 瞬态上读出来的，**不能推出"Kw 越大末速越低"**。

**想甩掉动量只能靠外力矩**：绕棱总角动量满足 `dH/dt = m·g·d·sin(θ_true)`，接触力与电机力矩都是内力。所以必须**先倾斜（把动量交给重力）、再回正**。比例项做不到（它的平衡点就是零力矩点），必须加对转速的**积分**项——积分改变的是平衡点本身。

|---|---|---|---|
| `point_balance` 默认（初倾 0.05°） | 0.48 rad/s | 0.001° | 已≈0 |
| `point_balance` 初倾 3° | 50（在升） | 0.0006° | 尚未冻结 |
| `point_balance` 初倾 5° | 110（在升） | 0.33° | 尚未冻结 |

| `flat_to_point_direct`（25 s） | 879.6 | 0.00° | 冻结 |

顶点默认看着"已经≈0"，只是因为初始倾角 0.05° 几乎没有瞬态；一旦带着真实动量进场（起立链把轮子充到 1140 rad/s），同样冻结在 507 / 880 rad/s。

> **我自己的测量 bug（留痕）**：`exp_wpark` 一度把 `flat_to_point` 报成"NOT BALANCED"。原因是该链落在 **(−1,1,1)/√3** 顶点，而我按 (1,1,1)/√3 算倾角。`exp_chain_tr` 用正确酉轴复测：`R·n₁ = (0.004, −0.004, 1.000)`，倾角 0.3°，`com_z` 25 s 恒定 0.12954，**该模式稳定通过**。

### 三、实现：转速积分项，做成预设而不是默认

- 控制图新增：`wsc` 累加 `w`（用与行走分支相同的 `clk` 差分 + 20 ms 钳位），**带泄漏** `wsc += (w − lamW·wsc)·dt`；棱律加 `+KiE·wsc(2)`，顶点律在**分配之后**对三个轮指令加 `+KiP·wsc`（转子动量是逐轮量，注入任务空间会被伪逆抹平）。
- `P.run.balancePreset = "fast" | "wheel_stop"`，两套预设各自留痕。**`fast` 逐位不变**（Ki=0 ⇒ `Ki*wsc` 恒为精确 0，已用 `diag_preset_baseline` / `diag_preset_compare` 逐字段核对，worst |diff| = 0）。
- 预设同时钉住倾角来源：`fast` → com，`wheel_stop` → attitude。**两者必须成对**，实测：attitude 倾角配 Ki=0 比 com 更差（30 s：飞轮 −254 rad/s 且仍在掉，com 是 1071 冻结）。

### 四、扫参：机构是通的，功能不成立

**符号**（20 s，com 倾角；代数预言的负号是错的）：`+KiE` 单调压低转速（0→983、1e-5→893、3e-5→595、1e-4→198）；`−KiE` 反向且 −3e-5 起翻倒。第四次出现"代数符号与实测相反"，与 Kw 那次同一模式。

**幅值**（40 s，com 倾角）：`KiE = 1e-3` 时飞轮 **−26.1 rad/s**（上限 1800 的 1.5%），`2e-3` 翻倒。

**63 s 的四组对照（决定性）**：

| 配置 | 飞轮末速 | 倾角末值 | 倾角峰值 | `com_x` |
|---|---|---|---|---|
| **fast（com 倾角，Ki=0）** | 1034.3 | **+0.005°** | 1.00° | 8.2 mm |
| attitude 倾角，Ki=0 | −1173.5 | −5.69° | 6.14° | 98.5 mm |
| com 倾角，Ki=1e-3 | 206.2 | −5.91° | 6.25° | 100.7 mm |
| attitude 倾角，Ki=1e-3 | **10.9** | −6.88° | 7.23° | 108.9 mm |

**转速确实被压到 0 了**（1092 → 10.9 rad/s），但每一项改动——积分项、attitude 倾角、或两者——都会让方块在 60 s 内倾到 −6°、`com_x` 漂到 100–110 mm（方块边长的 2/3），也就是**在倒下去的路上把转子甩掉了**。

**泄漏没有修好它**：`lamW` 从 0 扫到 2，每一条都停在 −6° 和 ~110 mm。**一个"原因"变了而结果不动的现象，其成因就不是它。**对照表说明真正的原因：**只有 com 倾角 + 无积分这一组能把方块立住**，任何对倾角来源或力矩律的改动都会放过方块的慢速倾覆模态。所以障碍是结构性的，不是增益：**挡住甩轮的那条反馈，正是把方块立住的那条反馈。**

**这个慢模态也解释了上一次回退**：先前用 `thetaBdot = −Ki·w` 的积分尝试被记为"行为反复无常"而回退，归因写的是"变步长下有效增益随步型变化"。实测表明是**这个慢模态的跑飞**，与积分器的步长无关（`dt` 用同一 `clk` 差分并钳位）。

**30 s 看不出来**：同一个设置在 30 s 时读作"飞轮 −12 rad/s、倾角 −1.3°"，看着像通过。**长跑是必需的**，这一条值得单独记住。

| 1e-4 | 3132.3 | 46.78° | 0.07461 | 翻倒 |
| 3e-4 | 3132.3 | 46.78° | 0.07464 | 翻倒 |
| 1e-3 | 3132.5 | 46.78° | 0.07461 | 翻倒 |

**一加就倒，正负都倒，最小的 1e-4 就倒。** 顶点的余量本来就小（捕获域 ≈3.5°，见审计一节），三个轮同时被注入力矩等于直接把捕获域吃掉。起立链 `flat_to_point_direct` 同样：`KiP = 1e-4` ⇒ `com_z` 掉到 0.07462（平放）、飞轮 3129 —— **起立本身也活不过积分项**。

于是用户这个问题的答案分两半：

- **点平衡本来就已经是"稳定后飞轮转速很低"**：出厂初始倾角 0.05° 时末速 **0.48 rad/s**（上限的 0.03%），给到 3° 的真实瞬态也只有 **50 rad/s**。所以不需要任何改动。
- **但"带着起立动量进场"的两种链**停在 **507 / 880 rad/s**，而这两种情况**甩不掉**——任何非零积分增益都让它立刻翻倒。

### 六、按用户澄清的口径（"近似为 0"即可）复测：还是撑不住

用户澄清：目标**不是严格等于 0，而是 0 附近、近似为 0**。这确实放宽了很多，但结论不变，只是原因更清楚了。

**先看好消息：点平衡本来就满足这个口径**，不需要任何改动——

| 顶点情形（`fast` 预设，Ki=0） | 飞轮末速 | 占上限 |
|---|---|---|
| 出厂初始倾角 0.05° | **0.48 rad/s** | 0.03% |
| 初倾 3° | **50.1 rad/s** | 2.8% |
| 初倾 5° | 110 rad/s | 6% |

**棱平衡则不行**：`fast` 预设冻结在 1092 rad/s（61%）。加积分项后**前 40–70 s 确实到了"近似为 0"**（148–188 rad/s，8–10%），但随后方块倾覆。`exp_wzero("hold")`，90 s，com 倾角：

| `KiE` | 前 40 s 飞轮 | 倾角在 40 s | 之后 | 结局 |
|---|---|---|---|---|
| 1e-4 | ~某值 | −2.45° | 倾角单调 −3.5→−5.3°，`com_x` 到 170 mm | ~80 s 翻平，飞轮顶 1800 |

**三条都是"慢 80 秒的同一个翻倒"，不是有界平衡。** 积分项买到的是时间（40–70 s 的"近似为 0"），不是可持续的状态。

再叠加一节的对照，结论是一致的：**com 倾角 + 无积分是唯一能把方块立住的组合**；一旦为了甩轮而引入持续力矩，方块那条慢速倾覆模态就过不去。所以即使用户放宽到"近似为 0"，棱平衡与两条起立链（507 / 880 rad/s）**仍未达成**。

**要真正做成，需要的是串级**（内环姿态 + 外环动量，并把那条慢模态显式镇定/加约束），而不是再调一个增益。本轮的机构与全部数据已为那条路铺好。

### 七、结论与交付

- `P.run.balancePreset` 默认 **`"fast"`**，已验收行为逐位不变。
- `"wheel_stop"` 的机构**已实现且实测有效**（转速 1092 → 11），但**未验收**：它满足不了"稳定后飞轮≈0 **且** 方块仍然立着"。参数文件里已按此写明，并明确标注 **do NOT enable it and call it a pass**。
- 保留该机构的理由：执行通路是通的，未来若做**串级**（内环姿态 + 外环动量，并显式镇定那条慢模态）可以直接复用。
- 复现：`exp_wtrace`/`exp_wpark`/`exp_chain_tr`（基线证据）→ `exp_wzero("edge"|"tilt"|"long"|"ctrl")`（扫参与对照）。

### 八、模态辨识（`exp_edgemode`）：倒的是**偏航 + 侧移**，不是俯仰

上一轮我把失败的成因叫"慢速倾覆模态"却从未辨识它。补上：用方块**世界系角速度的逐轴累积**（`cubli_rate` 积分，累积而非姿态角——姿态角会折叠），90 s 四组：

| 配置 | 飞轮末值 | 倾角末值 | 累积绕 X（横滚） | 累积绕 Y（俯仰） | **累积绕 Z（偏航）** | `comX` | `comY` | 结局 |
|---|---|---|---|---|---|---|---|---|
| **a 现用（com，Kw=+2e-4）** | 918.5 | −0.12° | −7.1° | −7.8° | **−0.3°** | 7 mm | **−139 mm** | **立着** |
| b com + 积分 KiE=3e-4 | 1809 | 45° | −19° | +21° | **+44°** | 168 mm | −233 mm | 翻倒 |
| c attitude + Kw=+2e-4 | −1665 | −8.9° | +7.5° | −19.6° | **+53°** | 140 mm | −281 mm | 跑飞 |
| d **attitude + Kw=−2.2e-4（串级）** | −1807 | **45°（t=15 就倒了）** | −2.0° | +52.5° | +7.3° | 106 mm | −14 mm | **翻倒** |

**结论一：能立住的唯一配置，偏航累积只有 −0.3°；两个倒掉的配置，偏航累积到 44° 和 53°。**倒的是**偏航 + 沿棱的侧移**，不是俯仰。而棱模式的律里**完全没有偏航反馈**（只有顶点律有 `−KyawP·ω₃`），所以靠加一个转速外环**修不到**——外环管的是转子动量，不是偏航。

**结论二：串级本身也当场失败。** `attitude + Kw=−2.2e-4`（即 `θ_ref = −k·w`、k=1e-4，展开就是现有 `Kw` 项取负号，零新状态量）——理论线性化说 k<4.35e-4 都稳、w 大约 2.7 s 衰减完，**实测 t=15 s 已经翻平、飞轮顶死 −1807**。

**这是代数在这个项目上第四次输给实测。根因值得单独记住：那个降阶模型（θ, w）完全没有平移/接触自由度，而这台机器的慢动态恰恰由它们主导**（d 组 15 s 内 `comX` 就滑了 84 mm）。所以这条降阶模型对慢模态的预测**不能用**，前三次"代数符号错"多半也是同一个原因，不是单纯的符号错。

**结论三（顺带查出，属既存问题）**：现用配置的 `comY` 在 90 s 内**单调漂到 −139 mm**（≈1.5 mm/s，接近方块边长），而且看不出有界。因为接触线沿 Y，沿 Y 的滑动在几何上不会掉下去，所以它不是"失败"，但它是**没有指令的持续平移**，且远超过既有口径 `P.contact.accept.comXYDriftMax = 5e-3`（5 mm）。另外现用配置的飞轮在 90 s 内其实**不是严格冻结**：t=45 s 峰值 1130 → t=90 s 降到 918（约 0.3 rad/s²），是极慢的衰减。30 s 看不到，又一次是长跑改写了结论。

### 九、补偏航回路：压住了偏航，但轮速需求仍未达成（含一次已撤回的错报）

> **⚠️ 本节的结论已被第十节推翻，请先读第十节。** 本节说"偏航打死一切甩轮尝试"——那是在**接触求解器 1 ms** 下测的，而那个步长上偏航主要由数值伪影驱动。换到 0.5 ms，同一个配置 `KiE=3e-4` 反而**立着且轮速 7.3 rad/s**。本节保留作为留痕（包括那次从单通道读数得出的错误结论）。

**做法（最小改动，零新状态量）**：棱模式的律原本**完全没有偏航反馈**（只有顶点律有 `−KyawP·ω₃`）。几何上，棱姿态 `R = RotY(45°)` 下 Wheel X 的轴是世界 `(0.707,0,−0.707)`、Wheel Z 是 `(0.707,0,0.707)`，**世界 Z 分量相反**，所以**反号驱动**它们就得到纯世界 Z 力矩——正好是棱→顶点跳（同号驱动得纯世界 X 力矩）的镜像。加一个参数 `P.run.wheelStop.Kyaw`，默认 0。

**它确实治好了偏航**：`KiE=3e-4` 下扫 Kyaw——0 在 75 s 翻倒（偏航 48°）、0.1 翻倒、**0.3 活满 120 s**、0.8 立即翻倒。偏航从累积 45–53° 变成有界的 12–31°。**但从 75–80 s 翻倒变成活满 120 s，不等于需求达成。**

**用三轮范数复测（`exp_yaw`，120 s）——这是关键，也是我犯的错**：

| `KiE` | `Kyaw` | Y 轮末值 | **三轮范数末值** | **范数峰值** | `wX` | `wZ` | 倾角末值 |
|---|---|---|---|---|---|---|---|
| 0 | 0 | 971 | 971 | 1137 | 0 | 0 | +0.01° |
| 2e-4 | 0.3 | **34** | **812** | **2386** | +573 | −573 | −0.64° |
| 3e-4 | 0.3 | 150 | 512 | 1752 | +346 | −346 | −1.71° |
| 5e-4 | 0.3 | 16 | 1009 | 2372 | +713 | −713 | −3.70° |

> **撤回**：我先报过一次"达成",依据是 `w_y` 降到 34 rad/s。**那是只读一个通道**——这一轮我第一次跑 `exp_yaw` 时打印的是 `max(abs(wy))`,而正确度量是三轮范数。好在同一批数据里 X/Z 的顶死是可查的,复测当场否掉。这一类错误本项目已经犯过多次(折叠度量、com_x 当倾角),所以这次**写进文档而不是悄悄改掉**。

**结论：Y 轮抽空的动量只是搬进了 X/Z 差动对。** 总动量 `Y: 0.097 → 对: 0.081 N·m·s`,基本不变;三轮范数**更差**,峰值 1752–2386 对 1800 上限。

**为什么偏航这一轴修不了（结构性）**：
1. **速率阻尼消不掉恒定扰动。** 偏航的恒定扰动是接触摩擦,回路必须持续出力;持续出力就攒动量。这是和俯仰同样的道理,只是换了轴。
2. **偏航动量在接触之外没有外力矩来源,所以根本甩不掉。** 俯仰的转子动量至少还能靠"倾斜→交给重力"(实测只需 `∫sinθ dt = 0.13 rad·s`,即 3° 倾角 2.7 s);偏航**没有对应的动作**,接触摩擦力矩是唯一的偏航外力矩,而它本身就是那个要对抗的扰动。所以 X/Z 只能一直存着。

因此 `wheel_stop` **仍标 NOT ACCEPTED**,`P.run.balancePreset` 默认仍是 `"fast"`(**逐位不变**,`diag_preset_compare` worst |diff| = 0,已核四轮)。

### 十、★ 根因是求解器步长：「偏航打死一切」是数值伪影，0.5 ms 下需求达成

**这一节推翻第九节，也是这一整轮真正的收获。**

#### 触发它的那次自查

我原本要验证"轮位不对称 / `I_xy = −1.5e-4` 是根因"，先查文档——**发现这个假设 [`CUBLI_G2A_TEST_PROTOCOL.md`](history/CUBLI_G2A_TEST_PROTOCOL.md) 早就证伪过**（删掉三只飞轮做成完美对称体，ODE1 偏航只从 302° 降到 61°，而对称刚体不可能物理自转；驱动量是积分器）。我没先读记录就提出来，这是我的错。

但那条记录给了更好的线索：它说偏航的驱动量是**积分器**，而**当时跑的是 ODE1——现在是 ODE3**。于是做变步长对照（`exp_yaw_numeric`）。

#### 第一次跑出来八个结果逐位相同——因为设置根本没生效

`P.sim.localSolver` 是在 `build_cubli_clean_cubli()` **建模型时**读进去的，循环里改 `P` 不重建模型等于没改。我加了 `set_param` + **回读断言**才拿到真数据。这一轮同类"变量没变就下结论"已经是第三次（前两次：`run.edge.Kyaw` 改名后失效、单通道 `w_y`）。**教训：任何"扫参"都要断言参数真的变了。**

#### 真数据（90 s，棱平衡）

| 配置 | 求解器 | 步长 | 偏航累积 | 倾角末值 | 三轮范数 | 结果 |
|---|---|---|---|---|---|---|
| fast（基线） | ODE3 | 1 ms | −0.3° | −0.12° | 918 | 立住 |
| fast | ODE3 | **0.5 ms** | **−18.1°** | −1.37° | 944 | 立住 |
| fast | ODE1 | 1 ms | **2947°** | −44.9° | 1815 | **翻倒** |
| fast | ODE2 | 1 ms | −801° | −45.0° | 1812 | **翻倒** |
| `KiE=3e-4` | ODE3 | 1 ms | 44° | 45° | 1809 | 翻倒 |
| **`KiE=3e-4`** | **ODE3** | **0.5 ms** | 55.7° | −13.5° | **7.3** | **立着** |

**偏航绝大部分是数值伪影**：能立住的基线自己在 1 ms 是 −0.3°、0.5 ms 是 −18°、ODE1 是 2947° 并翻倒。**第九节那条主线因此作废。**

#### 达成要求的配置（`exp_fine` / `exp_fine_long`，300 s，ODE3 @ 0.5 ms，**不加任何偏航项**）

| `KiEdge` | 三轮范数（300 s 全程） | 倾角 | `wX`/`wZ` | 结局 |
|---|---|---|---|---|
| **0（基线）** | 430 → 944 → 1179 → **1807 顶死** | 走到 **−45°** | 0/0 | **约 230 s 翻倒** |
| **3e-5** | **73…252 之间有界，末值 154** | **±0.44°（峰值 1.12°）** | **0 / 0** | **300 s 立着** |

- **轮速从 944 降到 73–252（上限的 4–14%）**，倾角留在门槛内且余量很大，**X/Y 精确不参与**——正是用户要的三条。
- 不是尖点：`1e-5→210`、`3e-5→89`、`1e-4→267`，都远低于基线 944。量级对就行。
- **代价：这个设置依赖步长。**同一个 `KiE=3e-5` 在出厂 1 ms 下**无效**（轮速停在 924）。而且**基线自己在 0.5 ms 下 230 s 就倒了**——现有棱平衡根本没有长期稳定性，只是从没跑那么久。

#### 仍未决（如实记录）

1. **`com_x` 仍在漂**：300 s 漂到 55 mm（约 0.18 mm/s），看不出有界。不会掉下棱（沿接触线滑动几何上可存活），但是无指令运动。
2. **轮速在 73–252 之间振荡**而不是静止。更小或带泄漏的环路能否收紧，未测。
3. **整个项目要不要搬到 0.5 ms 是项目级决定**：那会作废所有在 1 ms 下记录的数字，包括 `fast` 预设（它的偏航 −0.3°→−18°、倾角 −0.12°→−1.37°，仍立着但数字全变）。
